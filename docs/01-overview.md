# 01 このサーバは何か

## 1. 一行で

**Windows に最初から入っている音声を、OpenAI 互換の HTTP API で喋らせる常駐サーバ。**

## 2. なぜ作るのか

高品質な TTS エンジンは、たいてい GPU と VRAM を要求する。モデルの取得にも時間と回線が要る。
そこまでの品質は要らない場面 — **とにかく喋らせたい**、**VRAM に余裕が無い**、**回線が細い** —
のために、置いて叩くだけで動くものが欲しい。

Windows には日本語の声が最初から入っていて、GPU も要らず、1 文を 100 ms 以下で喋る
（実測値は [03](03-windows-speech.md)）。足りないのは **`/v1/audio/speech` を喋る薄い層**だけだった。

### 位置づけ

**「本命の代わり」ではない。** 声の質と機能の落差は大きい。参照音声も、話し方の指定も、
seed による再現性も無い。**そのことを利用者に隠さない**（§3）。

### なぜ常駐なのか

`powershell.exe` を都度起動して喋らせる方式は成立しない。プロセス起動だけで
**1,834 / 2,180 / 2,606 ms**（実測 3 回）かかり、合成そのもの（100 ms 前後）の **15〜22 倍**になる。
起動コストを 1 回に畳むために常駐させる。

## 3. 一番大事な決めごと — 無い機能をどう返すか

OpenAI 互換の API には、Windows の音声合成に**存在しない**パラメータがいくつも来る。
参照音声、話し方を文章で指定する caption、seed、サンプリングのステップ数。

**受け取って黙って捨てる。エラーにしない。**

エラーにすると、利用者が参照音声を 1 つ設定しただけで**生成が全件失敗する**。
「対応していないので無視した」と「壊れた」を区別できない状態でエラーを返すのは、
落差を伝えるどころか、原因の分からない障害を作るだけになる。

**ただし「黙って無視される」のは、それ自体が最悪の体験でもある。**
利用者が「caption を書いたのに効かない」と延々悩む余地を残してはいけない。
クライアントを一切変えずに伝えられる口は **`/health` の `model` 名**しかない
（多くのクライアントがそのまま画面に出す）。だからそこで必ず名乗る:

```
Windows 内蔵音声 / Microsoft Ayumi（参照音声・caption・seed は非対応）
```

この文字列の出典は `Contract/HealthResponse.ModelName`。

## 4. やること

| | |
|---|---|
| `POST /v1/audio/speech` | OpenAI 互換 + 拡張オブジェクト。**wav バイナリのみ**返す |
| `GET /health` | 稼働状態・声・音声フォーマット・同時実行数 |
| `GET /v1/models` | 疎通確認の口 |
| `GET /v1/audio/voices` | この PC で使える声の一覧 |
| 声の切り替え | 起動オプション `--voice` と、リクエストの `voice` / `model` |
| `speed` | Windows 側の話速へ写す |
| 48 kHz / 16bit / モノラルで返す | 生の出力は 16 kHz なので 3 倍へ上げる（[02](02-http-contract.md) §5） |

## 5. やらないこと

意図的に外している。**どれも「おまけ」の範囲を超える**か、Windows 側に対応する概念が無い。

| | なぜ |
|---|---|
| 参照音声（`ref_wav`） | Windows の音声合成に声を真似る機能が無い |
| Voice Design の caption | 同上 |
| `seed` / `num_steps` / `cfg_scale_*` | 生成モデルではないので対応する概念が無い |
| mp3 / flac / opus での出力 | 符号化器の依存が増える。変換は呼ぶ側で |
| SSE での進捗通知 | 合成が速すぎて刻む意味が薄い（[02](02-http-contract.md) §4.2） |
| 読点の間 / 句点の間の細かい制御 | Windows 側は `Default` / `Min` の 2 段しか無く、数値では指定できない |
| SSML の受け付け | 入力に信頼できないマークアップを混ぜる口を開けたくない |
| インストーラ / サービス登録 / 自動起動 | 置いて叩くだけ、を壊さない |
| 認証・TLS | ループバック前提。外に出すなら手前にリバースプロキシを置く |

## 6. 過剰設計のシグナル

どれかが出たら、機能を足す前に設計を見直す。

- `Speech/` の外に WinRT の型が漏れた
- `Speech/` が `HttpContext` を知っている
- `Contract/` にフィールドを足そうとしている
- 単一 exe を軽くするために `PublishTrimmed` を有効にしたくなった
- 「エンジンの切り替え」を抽象化したくなった（このサーバが喋らせるのは Windows の声だけ）
- 設定ファイルを読みたくなった（起動オプションで足りなくなったら、まず本当に必要か疑う）
